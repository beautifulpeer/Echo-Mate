# yolov5_demo 逐文件讲解版

## 1. 这个 demo 的作用

yolov5_demo 是 Echo-Mate 里的板端视觉识别示例。

它主要做的是：
- 打开摄像头
- 读取视频帧
- 调用 RKNN 版 YOLOv5 模型推理
- 对结果做后处理
- 把框和类别显示到 LCD 上

同时，它还有另一层价值：

> 不只是独立 demo，也能被 DeskBot 作为相机能力模块复用。

---

## 2. 顶层结构怎么理解

这个 demo 主要分成三块：

### A. 入口与业务源码
在 `cpp/`

### B. 模型文件与标签
在 `model/`

### C. 第三方推理/图像库
在 `cpp/3rdparty/`、`cpp/lib/`、`cpp/rknpu2/`

---

## 3. cpp 目录逐文件讲解

### 3.1 CMakeLists.txt
这是视觉 demo 的构建入口。

它做的事情包括：
- 指定 ARM 交叉编译工具链
- 查找 OpenCV
- 编译核心库 `yoloCameraCore`
- 把 `postprocess.cc`、`AIcamera_c_interface.cc`、RKNN 推理文件编进来
- 生成最终可执行文件
- 安装模型文件到部署目录

所以它的作用不仅是“编译一个程序”，还负责把部署目录一起整理好。

### 3.2 main.cc
这是独立运行版的入口文件，也是最值得看的源码。

它的完整流程非常直观：

1. 停掉默认占用摄像头的后台服务
2. 加载 yolov5 模型
3. 初始化后处理
4. 打开 framebuffer 和摄像头
5. 每帧做 resize
6. 调用模型推理
7. 绘制识别框和类别文本
8. 把结果输出到屏幕上
9. 实时计算 FPS

这份文件最适合拿来理解“板端目标检测最小闭环”。

### 3.3 main2.cc
从命名看通常是一个备用入口或测试入口。

这类文件一般用来做：
- 对比实验
- 简化测试
- 单独验证某段功能

如果你主流程已经看懂，可以再看它是怎么做调试的。

### 3.4 yolov5.h
这里通常声明 RKNN 上下文、模型初始化、推理、释放等接口。

它定义的是整个视觉推理模块对外暴露的能力边界。

### 3.5 postprocess.h
定义检测结果结构体，例如：
- 检测框
- 概率
- 类别 ID
- 检测结果列表

还声明了 NMS、标签加载、后处理相关接口。

### 3.6 postprocess.cc
这里是后处理核心实现。

主要负责：
- 读取类别标签
- 计算候选框分数
- NMS 非极大值抑制
- 把模型输出转成最终目标框列表

如果你以后想调：
- 阈值
- 类别标签
- 检测框筛选策略

这里是重点。

### 3.7 AIcamera_c_interface.h
提供给外部工程调用的 C 接口，声明了：
- 启动 AI 相机
- 停止 AI 相机
- 获取图像缓冲区

### 3.8 AIcamera_c_interface.cc
这是它被 DeskBot 集成的关键。

它做的事情是：
- 在后台线程里持续做推理
- 把识别后的图像写入一个共享缓冲区
- 让外部 UI 页面可以直接拿到缓冲数据并显示

所以它不是独立应用逻辑，而是“可复用的相机能力适配层”。

## 4. model 目录

这个目录放的是模型和标签资源。

常见内容包括：
- `*.rknn`：推理模型
- `coco_80_labels_list.txt`：类别名称列表
- `bus.jpg`：测试图片或示例图片

如果你以后想换成自己的模型，这里就是最常改的目录之一。

---

## 5. rknpu2 与 3rdparty 目录

### 5.1 rknpu2/
这一部分通常存放和 Rockchip NPU 推理相关的适配代码，比如：
- 模型初始化
- 输入输出 tensor 管理
- 推理调用封装

### 5.2 3rdparty/
主要是一些底层依赖，例如：
- 图像绘制
- 文件工具
- 内存分配
- RGA / DMA 等支持

### 5.3 lib/
通常放预编译好的 OpenCV 或相关依赖库。

### 5.4 include/
放头文件集合，供编译时引用。

这一整块更偏平台适配层，先知道它们存在即可，不必一上来全部细读。

---

## 6. rv1106_yolov5_demo 目录

这是构建安装后的部署目录。

通常包含：
- 可执行文件
- model 子目录
- 运行需要的动态库

你真正复制到板子上运行的，往往就是这个目录。

---

## 7. 这个 demo 和 DeskBot 的关系

这个 demo 不是孤立的。

它实际上已经被设计成两种用法：

### 用法 1：独立运行
直接运行 `main.cc` 生成的程序，查看摄像头识别效果。

### 用法 2：嵌入 DeskBot
通过 `AIcamera_c_interface` 暴露的 C 接口，把识别图像和能力挂到 DeskBot 的 YOLO 页面里。

这说明仓库作者不是把它当一次性样例，而是把它当成一个“可插拔视觉模块”。

---

## 8. 推荐阅读顺序

建议你按下面顺序看：

1. `cpp/main.cc`
2. `cpp/CMakeLists.txt`
3. `cpp/yolov5.h`
4. `cpp/postprocess.h`
5. `cpp/postprocess.cc`
6. `cpp/AIcamera_c_interface.h`
7. `cpp/AIcamera_c_interface.cc`
8. `model/` 里的模型和标签文件

---

## 9. 一句话总结

yolov5_demo 的核心结构是：

> 摄像头采集 + RKNN 推理 + 后处理 + 屏幕显示，并且通过 C 接口留好了给 DeskBot 复用的能力出口。
