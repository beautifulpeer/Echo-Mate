# Echo-Mate 建议阅读路径

## 1. 最推荐的阅读顺序

如果你第一次接触这个工程，我建议按下面顺序读：

### 第一步：先看项目总览
- 根目录 README
- Demo 目录 README
- SDK 目录 README

目的：先建立“这个仓库不是单 demo，而是项目集合”的整体认识。

### 第二步：看 DeskBot_demo
目的：理解最终产品形态。

重点关注：
- `main.c`
- `gui_app/ui.c`
- `gui_app/pages/`
- `common/sys_manager/`

### 第三步：看 AIChat_demo 的 Client
目的：理解板端语音应用如何组织。

重点关注：
- `main.cc`
- `Application/`
- `StateMachine/`
- `Audio/`
- `WebSocket/`
- `c_interface/`

### 第四步：看 AIChat_demo 的 Server
目的：理解服务端的 AI 流程如何被串起来。

重点关注：
- `main.py`
- `ws_server.py`
- `service_manager.py`
- `handle/`
- `services/`

### 第五步：按需看视觉 demo
如果你想做摄像头/识别：
- 看 yolov5_demo
- 看 rkmpi_demos

---

## 2. 适合不同目标的入口建议

### 想改 UI
先看 DeskBot_demo 的 `gui_app/pages/`

### 想加新功能页
参考现有 page 模板，再把它注册到 `ui.c`

### 想扩展语音对话能力
优先改 AIChat_demo/Server 的 `services/` 和 `models/`

### 想让机器人执行更多动作
重点看：
- Client 端的 Intent 注册
- DeskBot 的 ChatBotPage 处理逻辑
- GPIO/电机控制层

### 想做视觉扩展
先以 yolov5_demo 为模板，再参考 rkmpi_demos 的视频链路样例

---

## 3. 我对这个仓库的总体判断

这个仓库已经不是“从零教学式的小例子”，而是一个相对完整的项目原型：

- 有板卡 SDK
- 有 GUI
- 有设备配置
- 有 AI 语音链路
- 有视觉识别链路
- 有面向最终桌面机器人场景的整合思路

所以后续你如果要继续做，我建议把它当成：

> 可二次开发的机器人项目母体

而不是只把它当成普通 demo 仓库。

---

## 4. 你下一步最值得做的事

### 方向 A：快速跑通
- 先跑 Server
- 再跑 AIChat Client
- 最后跑 DeskBot

### 方向 B：快速理解架构
- 先读本目录下的分析文档
- 再按主线把源码入口过一遍

### 方向 C：开始改功能
优先挑一个简单需求，例如：
- 增加一个新页面
- 替换天气接口
- 增加新的语音意图
- 把机器人动作指令扩成更多 GPIO 行为
