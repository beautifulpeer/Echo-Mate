# Echo-Mate 各 Demo 功能说明

## 总览

本仓库里的核心 demo 可以理解成四类：

| Demo | 作用 | 运行位置 | 在整机中的地位 |
| --- | --- | --- | --- |
| DeskBot_demo | 完整桌面机器人 UI 与功能集合 | RV1106 / Linux 模拟器 | 主 demo、整机应用 |
| AIChat_demo | 语音对话助手，分 Client 和 Server | Client 在板端，Server 在电脑 | 机器人“会听会说会回复”的能力来源 |
| yolov5_demo | 摄像头目标识别 | RV1106 | 独立视觉识别 demo |
| rkmpi_demos | Luckfox/Rockchip 多媒体与流媒体例程集合 | RV1106 / RV1103 | 偏底层能力样例 |

---

## 1. DeskBot_demo 是干嘛的

这是整个项目里最像“最终产品”的 demo。

### 它实现了什么

它基于 LVGL 做了一个小型桌面机器人系统，把多个功能做成了页面化桌面应用，包括：

- 首页与应用图标桌面
- 设置页
- 天气页
- 日历页
- 聊天机器人页
- YOLO 页面
- 2048、记忆游戏、木鱼等轻应用
- 画板和计算器

### 它的本质

你可以把它理解成：

> 一个运行在 RV1106 上的迷你 Linux 图形桌面 + 多个内置小应用。

### 为什么它最重要

因为它把下面这些零散能力融合到了一起：

- 屏幕显示
- 触摸与手势交互
- 系统参数保存
- 网络状态显示
- AI 语音助手入口
- 机器人运动控制

也就是说，DeskBot_demo 是“整合层”。

---

## 2. AIChat_demo 是干嘛的

这是一个**独立的 AI 语音助手 demo**，采用 Client/Server 分体架构。

### Client 端作用

Client 用 C++ 写，主要跑在板端，负责：

- 录音
- 音频编码与播放
- WebSocket 通信
- 状态机切换
- 接收服务端返回的意图和语音结果

### Server 端作用

Server 用 Python 写，通常跑在电脑端，负责：

- WebSocket 服务
- 鉴权
- VAD 语音活动检测
- ASR 语音转文字
- 意图识别
- LLM 对话生成
- TTS 文字转语音

### 这个 demo 最终效果

板子说话，电脑服务端理解后生成回复，再把语音返回板子播放；如果识别到函数调用，例如机器人移动，也会把指令回传给客户端。

### 它和 DeskBot 的关系

DeskBot 中的聊天页并不是重新写了一套聊天逻辑，而是**通过 C 接口把 AIChat_demo 的 Client 能力嵌进了 LVGL 页面中**。

所以：

- AIChat_demo 可以独立运行
- 也可以作为 DeskBot_demo 的一个子能力模块

## 3. yolov5_demo 是干嘛的

这是一个典型的板端视觉 demo。

### 功能

- 调用摄像头采集画面
- 将图像送入 yolov5 模型推理
- 识别画面中的目标
- 在 LCD 上画框并显示类别和置信度

### 技术路线

- RKNN 模型推理
- OpenCV-mobile 图像处理
- framebuffer 屏幕显示

### 适合拿来做什么

这个 demo 很适合用来学习：

- RV1106 上如何加载模型
- 如何读摄像头
- 如何把推理结果实时显示在屏幕上
- 如何做一个完整的“视觉采集 → 推理 → UI输出”闭环

---

## 4. rkmpi_demos 是干嘛的

这是 Luckfox 提供的或基于其生态整理的一组 **RKMPI 多媒体例程**。

### 包含的方向

- RTSP 视频流
- OpenCV 处理
- 图像抓拍
- RetinaFace 人脸检测
- YOLO 目标识别
- OSD 叠加显示

### 它的定位

与其说它是 Echo-Mate 专属应用，不如说它更像：

> 给 RV1106 / RV1103 做多媒体、视觉、流媒体开发时的参考样例库。

如果你之后要扩展：
- 摄像头推流
- 人脸检测
- 网络视频预览
- 图像算法链路

这部分会很有参考价值。

---

## 5. 各 demo 之间是什么关系

可以用一句话概括：

- **DeskBot_demo**：最终整合出来的“桌面机器人系统”
- **AIChat_demo**：提供语音交互内核
- **yolov5_demo**：提供独立视觉识别示例
- **rkmpi_demos**：提供更底层/更丰富的视频与视觉样例

也就是说，这个仓库不是并列的几个毫无关系的小工程，而是一个“主工程 + 能力 demo 集”。
